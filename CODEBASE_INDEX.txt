## 🛠️ 2. DETAILED FILE-BY-FILE EXPLANATION

### 📁 Root Directory Configuration Files
*   **[Makefile](file:///home/symtuh/Documents/Projects/Krynox-Nexus/Makefile)**:
    The brain of local orchestration. Offers intuitive targets to standardise building, testing, cleaning, and scanning.
    Key targets:
    *   `make build`: Spawns module builder shell scripts with security-enhanced compiler flags (`-fstack-protector-strong`, `-fno-strict-overflow`, etc.).
    *   `make test-unit`: Compiles and runs `cmocka` unit tests with code coverage (`gcov`) support.
    *   `make test-integration`: Executes the `pytest` test suite to validate end-to-end pipeline conversions.
    *   `make security-scan`: Standard static analysis and architecture scan runner.
    *   `make reports`: Auto-generates the static premium dashboard page at `reports/index.html`.
    *   `make docker-build` / `make docker-scan`: Enables isolated multi-stage containerized validations.
*   **[AGENTS.md](file:///home/symtuh/Documents/Projects/Krynox-Nexus/AGENTS.md)**:
    Defines the zero-trust paradigm rules, active agent responsibilities, operational boundaries, and cybersecurity standards for the lead security engineer agent.
*   **[PROJECT_ACTIVITY_LOG.txt](file:///home/symtuh/Documents/Projects/Krynox-Nexus/PROJECT_ACTIVITY_LOG.txt)**:
    A sequential audit trail documenting major accomplishments, completed features, refactorings, and milestone releases.
*   **[README.md](file:///home/symtuh/Documents/Projects/Krynox-Nexus/README.md)**:
    The master guide detailing the quick start workflow, design architecture, system prerequisites, and status badges.
*   **[SECURITY.md](file:///home/symtuh/Documents/Projects/Krynox-Nexus/SECURITY.md)**:
    Establishes zero-disclosure policies, vulnerability reporting channels, and the remediation lifecycle for kernel drivers.

### 📁 .github/workflows/ (CI/CD Automations)
*   **[security-scan.yml](file:///home/symtuh/Documents/Projects/Krynox-Nexus/.github/workflows/security-scan.yml)**:
    The flagship automation pipeline. On every code push or pull request to the `main` branch, it:
    1. Sets up the execution runner.
    2. Installs required system dependencies (Clang, Cppcheck, Sparse, IBM Bob, etc.).
    3. Triggers static analyses, configuration validation, and architectural checks.
    4. Automatically runs the Python converter scripts to generate SARIF format outputs.
    5. Safely uploads the SARIF reports to the GitHub Security Tab for deep code scanning integration.
*   **[codacy.yml](file:///home/symtuh/Documents/Projects/Krynox-Nexus/.github/workflows/codacy.yml)**:
    Runs Codacy security and style static analysis on changed code to enforce standard code-quality gates.

### 📁 scripts/ (Tooling, Scanners & Converters)
*   **[deploy_sarif.sh](file:///home/symtuh/Documents/Projects/Krynox-Nexus/scripts/deploy_sarif.sh)**:
    A bash helper to upload generated SARIF results to GitHub via the REST API or GitHub CLI.
*   **[setup/install_tools.sh](file:///home/symtuh/Documents/Projects/Krynox-Nexus/scripts/setup/install_tools.sh)**:
    Installs build-essential, clang, cppcheck, sparse, cmocka, lcov, and python dependencies locally on Fedora/RedHat systems.
*   **[build/build_modules.sh](file:///home/symtuh/Documents/Projects/Krynox-Nexus/scripts/build/build_modules.sh)**:
    Drives module compilation, checking that security compiler flags are strictly enforced to counter binary-level exploitation.
*   **[security/run_static_analysis.sh](file:///home/symtuh/Documents/Projects/Krynox-Nexus/scripts/security/run_static_analysis.sh)**:
    Executes Clang Static Analyzer, Cppcheck, and Sparse sequentially. If findings are found, they are piped through Python converters to produce SARIF output.
*   **[security/run_ibm_bob.sh](file:///home/symtuh/Documents/Projects/Krynox-Nexus/scripts/security/run_ibm_bob.sh)**:
    Runs IBM Bob CLI, which evaluates the structural and architectural parameters of the module code to detect higher-level design vulnerabilities.
*   **[security/verify_kernel_hardening.sh](file:///home/symtuh/Documents/Projects/Krynox-Nexus/scripts/security/verify_kernel_hardening.sh)**:
    Queries `/boot/config-*` or `/proc/config.gz` to check if protective kernel features (e.g. stack protector, page table isolation) are compiled into the system.
*   **[security/generate_dashboard.py](file:///home/symtuh/Documents/Projects/Krynox-Nexus/scripts/security/generate_dashboard.py)**:
    Gathers all SARIF, Cppcheck, IBM Bob, and coverage inputs, compiling them into a visually stunning, responsive single-page HTML report (`reports/index.html`).

#### 📁 scripts/security/sarif_converters/ (Custom Python Normalization Engines)
*   **[base_converter.py](file:///home/symtuh/Documents/Projects/Krynox-Nexus/scripts/security/sarif_converters/base_converter.py)**:
    An abstract class representing the converter framework. It defines the `Finding` dataclass schema, provides path resolution logic, extracts source code snippets to display context directly in findings, maps severity keywords, and handles OASIS SARIF 2.1.0 schema generation.
*   **[cwe_mappings.py](file:///home/symtuh/Documents/Projects/Krynox-Nexus/scripts/security/sarif_converters/cwe_mappings.py)**:
    A local mapping dictionary pairing kernel-specific vulnerabilities (e.g. use-after-free, double free, bounds overflow) to their official Common Weakness Enumeration IDs (CWE-119, CWE-416, etc.) and severity classes.
*   **[clang_converter.py](file:///home/symtuh/Documents/Projects/Krynox-Nexus/scripts/security/sarif_converters/clang_converter.py)**:
    Regex-parses standard text output from the Clang Static Analyzer to extract file path, line, column, and warning messages into SARIF.
*   **[cppcheck_converter.py](file:///home/symtuh/Documents/Projects/Krynox-Nexus/scripts/security/sarif_converters/cppcheck_converter.py)**:
    Parses Cppcheck XML reports, normalizing element tags, severity levels, and embedding reference rules.
*   **[sparse_converter.py](file:///home/symtuh/Documents/Projects/Krynox-Nexus/scripts/security/sarif_converters/sparse_converter.py)**:
    Extracts kernel-specific sparse errors (such as mismatched locking contexts, dereferencing `__user` pointers in kernel space, and incorrect type casting).
*   **[bob_converter.py](file:///home/symtuh/Documents/Projects/Krynox-Nexus/scripts/security/sarif_converters/bob_converter.py)**:
    Transforms architectural findings from the IBM Bob JSON structure into valid SARIF records.
*   **[hardening_converter.py](file:///home/symtuh/Documents/Projects/Krynox-Nexus/scripts/security/sarif_converters/hardening_converter.py)**:
    Converts failed self-protection kernel parameters into actionable, high-priority SARIF items containing remediation advice.

### 📁 src/ (Kernel Module Implementations)
*   **[src/Makefile](file:///home/symtuh/Documents/Projects/Krynox-Nexus/src/Makefile)** and **[src/Kbuild](file:///home/symtuh/Documents/Projects/Krynox-Nexus/src/Kbuild)**:
    Define module building targets for the kbuild engine, mapping the final binaries `buffer_overflow.ko`, `use_after_free.ko`, `buffer_overflow_secure.ko`, and `hello_secure.ko`.

#### Intentionally Vulnerable Modules (Test Vector validation)
*   **[vulnerable/buffer_overflow.c](file:///home/symtuh/Documents/Projects/Krynox-Nexus/src/vulnerable/buffer_overflow.c)**:
    Demonstrates stack overflows (via raw `strcpy`), heap memory boundary violations (fixed allocation under `SMALL_BUFFER_SIZE` with unbounded `memcpy`), and insecure format string exposures in kernel printk logs.
*   **[vulnerable/use_after_free.c](file:///home/symtuh/Documents/Projects/Krynox-Nexus/src/vulnerable/use_after_free.c)**:
    Implements UAF routines (calling `kfree` on structure buffers and subsequently printing/mutating their members), double free violations (calling `kfree` twice on the same address), dangling pointers, and memory leaks.

#### Hardened & Secure Reference Implementations
*   **[examples/buffer_overflow_secure.c](file:///home/symtuh/Documents/Projects/Krynox-Nexus/src/examples/buffer_overflow_secure.c)**:
    A secure replacement module. Implements robust bounds checking, safe string buffers (using `strscpy`), validation limits on user-controlled sizes before allocation, and proper cleanups on write-handlers to negate stack and heap overflows.
*   **[examples/hello_secure.c](file:///home/symtuh/Documents/Projects/Krynox-Nexus/src/examples/hello_secure.c)**:
    A secure entry-level module showing proper structure initializations, proc boundaries, and compliant permissions.

    A `cmocka` mock test suite compiled with gcov profiling. Validates buffer copies, string formatting boundary constraints, and memory operations on mocked drivers to confirm security invariants.

    A rigorous end-to-end integration validation framework. Running in pytest, it dynamically:
    1. Tests individual SARIF converter implementations with mocked and live payloads.
    2. Validates generated output compliance against the official OASIS SARIF JSON schema.
    3. Confirms relative path operations, line/column bindings, and CWE mapping lookups.
    4. Simulates end-to-end scanner runs to verify robust fault tolerance.
